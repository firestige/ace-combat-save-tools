## 支持功能

- 列出三个存档槽的状态、余额、可购买机型数量和已拥有机型 ID。
- 明确选择一个已有存档槽修改资金。
- 开启所选槽全部 36 个机型的**购买资格**，仍需花钱购买，不免费赠送。
- 自动校验内外两层封装，备份后写入，检查非目标槽未变。
- [存档格式研究](docs/FORMAT.md)与 [Copilot skill](.github/skills/ace-combat-save-editing/SKILL.md)。

不创建空槽，不猜测游戏当前槽，不伪造通关历史，也不全开武器、涂装或勋章。

## 安装与使用

验证环境使用 Python 3.13。正式覆盖 `--apply` 仅支持 Windows。

```powershell
python -m pip install -r requirements.txt
$tool = '.github\skills\ace-combat-save-editing\scripts\aczero_save.py'
$save = 'C:\Program Files (x86)\Steam\userdata\<accountid>\2288340\remote\aczero\save\save.sav'

# 只读分析，显示全部三个槽。
python $tool --source $save

# 查看第二槽详情。
python $tool --source $save --slot 2

# 先生成解锁副本，不改来源。
python $tool --source $save --slot 2 --unlock-aircraft

# 关闭游戏后，备份并正式开启购买资格。
python $tool --source $save --slot 2 --unlock-aircraft --apply

# 将第二槽余额设为一百万，不是增加一百万。
python $tool --source $save --slot 2 --set 1000000 --apply
```

示例中的 Steam 路径和 `<accountid>` 必须换成自己的实际值。
来源为标准 Steam 路径时可推断 32 位账号 ID；处理其他目录下的副本时，
用 `--account-id` 显式提供原账号的 32 位 ID，不是 SteamID64。
`--amount` 只搜索数值；`--set` 才修改余额，且为**设置总额**。
仅在确实需要两项操作时，才组合 `--set` 和 `--unlock-aircraft`。

### 三槽选择与安全约束

JSON 的 `slots_before` / `slots_after` 列出 `slot`、`state`、`money`、
`available_aircraft` 和 `owned_aircraft_ids`。状态为 `occupied`、`empty`
或 `unknown`；空槽和异常槽不显示误导性的余额，而显示 `null`。
只读且未传 `--slot` 时，三槽都会列出，顶层详情字段沿用第一槽。

**任何修改都必须明确传入 `--slot 1|2|3`**。空槽或异常槽拒绝修改：
请先在游戏内正常建立战役并保存，不要伪造空槽标志。
工具核对公共头及非目标槽完整记录逐字节不变，只改目标字段与必要校验。
第三槽仍需进入游戏验证；即使第一、第二槽已验证，操作后仍应核对自己的结果。

## 备份、验证与恢复

没有 `--apply` 就不覆盖来源文件，只在新临时目录生成分析／候选副本；
可以用 `--output-dir` 指定输出目录。

正式写入前必须关闭游戏。工具创建同目录 ZIP 备份并核验内容，校验原文件，
限定修改字段，确认来源未被并发改写，再通过同目录临时文件原子替换。
写入后重新运行只读分析，再加载对应游戏槽验证。

恢复时关闭游戏，从选定 ZIP 解压原存档回来源目录。
Steam 云同步可能覆盖本地文件；须谨慎处理冲突，不要盲目修改云元数据。
保留备份直到游戏验证完成；工具不能保证免于损坏或云覆盖。

## 离线回归检查

```powershell
python tests\validate_slots.py
```

19 项 CLI 检查只使用合成数据，涵盖三个槽、单独／组合修改、其他槽保持不变、
必须明确指定槽、空槽／异常槽拒绝，以及“无任务”哨兵不被误判为空槽。
检查不读写实际存档，临时测试文件自动清理，不能替代游戏验证。
